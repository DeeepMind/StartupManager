# Startup Manager · 启动项管理器

> 识别并管理 Windows 上**所有**非系统开机启动项 —— 包括任务管理器看不见的那些。

一个轻量的 Windows 桌面工具，覆盖 **5 类启动方式**，其中「计划任务」和「Windows 服务」是大多数启动项工具根本扫不到的位置。

- **绿色免安装**：解压即用，不写系统目录，卸载只需删文件夹
- **可逆操作**：禁用从不删除任何东西，随时一键恢复
- **中文界面**：表头、提示、菜单全中文
- **开源自检**：内置 37 项自动化检查，可自行验证功能正常

---

## 一、为什么需要它

你在任务管理器「启动应用」里看到的，只是开机自启的一部分。

| 你以为的启动项 | 实际可能存在的位置 |
|---|---|
| 任务管理器 → 启动应用 | 只显示**注册表 Run** + **启动文件夹** |
| 软件设置里的"开机启动" | 可能写到了**计划任务**里 |
| 完全找不到 | 可能是 **Windows 服务**，在登录界面出现前就启动了 |

本工具把这 5 个位置一次性全部扫出来，并统一展示、统一管理。

### 覆盖的启动来源

| 来源 | 说明 | 能否直接操作 |
|---|---|---|
| **注册表 Run**（HKCU / HKLM / WOW6432Node） | 最常见的启动位置 | ✅ 启用 / 禁用 |
| **注册表 RunOnce** | 只运行一次，执行后自动删除 | ✅ 启用 / 禁用 |
| **启动文件夹**（当前用户 / 公共） | `shell:startup` 里的快捷方式 | ✅ 启用 / 禁用 |
| **计划任务** | 仅显示开机/登录触发的，过滤掉系统任务 | ✅ 启用 / 禁用 |
| **Windows 服务** | 自动启动的服务，可在登录前运行 | ✅ 启用 / 禁用 |
| **WMI 事件订阅** | 极隐蔽的持久化机制 | 👁 只读查看 |

## 二、快速开始

### 方式一：下载即用（推荐）

1. 下载 `StartupManager-1.0.0-portable.zip`
2. 解压到**任意普通目录**，例如 `D:\Tools\StartupManager\`
3. 双击 `StartupManager.exe`

> ⚠ **不要放在带有特殊权限限制的目录**（如某些带 Deny 规则的项目目录），
> 否则可能因无法写入临时文件而启动失败。普通用户目录、下载文件夹、D 盘工具目录均可。

> ✅ **无需安装 .NET 运行时**。本程序采用自包含发布（`--self-contained true`），
> .NET 8 运行时已随包分发，Windows 10 / 11 均可直接运行。

### 方式二：从源码构建

```powershell
git clone https://github.com/DeeepMind/StartupManager.git
cd StartupManager
.\build-release.ps1
```

产物：`dist\StartupManager-<版本>-portable.zip`

## 四、安全设计

本工具在**每一个可修改的位置都做了可逆设计**，没有任何"删除"操作。

### 禁用是如何实现的

| 来源 | 禁用时做了什么 | 如何恢复 |
|---|---|---|
| 注册表 | 写入 Windows 官方「启动审批」标记（`StartupApproved`），**不删除原值** | 点启用即可，原值从未被改动 |
| 启动文件夹 | 同样写审批标记，**文件留在原地** | 点启用即可 |
| 计划任务 | `schtasks /change /disable`，微软官方方式 | 点启用即可 |
| 服务 | `sc config "名称" start= demand`（改为手动） | 点启用，**自动还原原始启动类型** |

**与任务管理器互通**：注册表和启动文件夹的禁用使用 Windows 原生「启动审批」机制，
因此在任务管理器里看到的状态会与本工具**保持同步**，两个工具不会互相覆盖。

### 服务的特殊处理

服务启动类型有「自动」和「自动（延迟启动）」两种。本工具在禁用时会**记录原始状态**，
恢复时精确写回，不会把"延迟启动"的服务悄悄变成"普通自动启动"。

> 禁用服务时使用的是 **`demand`（手动）而非 `disabled`（禁用）**。
> 因为设为 `disabled` 会导致依赖该服务的程序无法启动，风险过大。

### WMI 订阅为何只读

WMI 事件订阅删除需要精确操作，误删可能影响系统。
因此本工具只展示（用于识别可疑项），不提供修改功能。

### 系统项判定规则

判断"是否 Windows 自带"时使用**多重信号**，而非单一条件：

```
服务：  二进制在 C:\Windows\ 下             → 系统
       或 发布者为 Microsoft / Windows (R)   → 系统
       或 无法解析路径 且 账户为 LocalSystem → 系统（保守处理）
```

> 早期版本曾用"以 LocalSystem 账户运行"作为唯一判据，
> 结果 Adobe、ZeroTier、NVIDIA 等第三方服务全部被误判为系统项而隐藏。现已修正。

## 五、权限说明

### 普通权限即可完成的操作

- 扫描全部启动项
- 启用/禁用：注册表 HKCU、当前用户启动文件夹、用户级计划任务
- 服务：部分需要管理员

### 需要管理员权限的操作

- 修改 HKLM（所有用户）注册表启动项
- 修改公共启动文件夹
- 修改系统级计划任务
- 修改服务启动类型

**遇到权限不足时**，程序会主动询问是否以管理员身份重新执行该操作，
确认后会弹出 UAC，由提权后的实例自动完成并告知结果，**无需手动敲命令**。

也可以直接右键 `StartupManager.exe` → 以管理员身份运行。

### 几个关键技术点

**1. 必须读取「启动审批」状态**

任务管理器禁用启动项时**不删除**原注册表值，而是写入 `StartupApproved` 标记：

```
HKCU\...\Explorer\StartupApproved\Run
数据格式：[0x02=启用 / 0x03=禁用] + 3字节保留 + 8字节FILETIME
```

只读原位置会导致所有"已被任务管理器禁用"的项全部误报为"已启用"。

**2. PowerShell 调用必须走临时文件**

```
❌ powershell -Command -        ← 从 stdin 喂脚本，在中文 Windows 上会静默失败
✅ powershell -File script.ps1  ← 且脚本必须是 UTF-8 带 BOM
```

**3. 失败必须暴露，不能静默返回空**

扫描器接口带 `LastError` 属性，任何失败都会汇总到界面警告栏，
避免出现"少了一整类启动项但界面看起来一切正常"的情况。

**4. 使用 TableLayoutPanel 而非裸 Dock 堆叠**

裸 Dock 对控件添加顺序极其敏感，容易出现控件溢出窗口导致布局错乱。
改用显式划分行后，网格能正确随窗口伸缩。

## 八、已知限制

| 限制 | 说明 |
|---|---|
| 仅支持 Windows 10 / 11（x64） | 依赖 Windows 特有的注册表、服务、计划任务 API |
| 计划任务只显示开机/登录触发 | 定时触发（每天/空闲时）的任务不算"开机启动"，不列出 |

## 九、卸载

绿色版**不写安装目录之外的内容**，卸载很简单：

1. 删除程序所在文件夹即可
2. 清理本工具产生的数据（可选）

### 本工具实际会写入的位置

| 内容 | 位置 | 何时产生 |
|---|---|---|
| 服务原始启动状态 | `%LOCALAPPDATA%\StartupManager\ServiceState\` | 禁用某个服务时 |
| 启动文件夹禁用备份 | `%LOCALAPPDATA%\StartupManager\DisabledStartupFiles\` | **仅当审批标记写入失败时的回退路径** |
| 注册表值备份 | `HKCU\Software\StartupManager\Disabled\` | **仅当审批标记写入失败时的回退路径** |
| PowerShell 临时缓存 | 程序目录 `.smcache` 或 `%LOCALAPPDATA%\StartupManager\cache` | 扫描计划任务/服务时 |

> **重要**：正常情况下禁用注册表项和启动文件夹项，使用的是 Windows 原生
> `StartupApproved` 标记，**不会**产生上面两处「回退路径」的备份。
> 只有 `StartupApproved` 写入失败且非权限原因时才会回退到移动值/移动文件的方式。

### 清理命令

```powershell
# 清理本工具数据（服务状态备份 + 可能的回退备份 + 缓存）
rmdir /s /q "%LOCALAPPDATA%\StartupManager"

# 仅当曾出现"回退路径"备份时才需要（多数情况下该键不存在）
reg delete "HKCU\Software\StartupManager" /f
reg delete "HKLM\Software\StartupManager" /f
```

> ⚠ 删除前请确认已通过界面把所有项重新启用。
> 如果是正常路径（审批标记）禁用的项，原值从未被改动，
> 直接删程序不影响它们——那些项仍保持禁用状态，可随时在任务管理器里重新启用。

## 十一、常见问题

**Q：扫出来的项比任务管理器多很多？**
正常。任务管理器只显示注册表 Run 和启动文件夹，本工具还包括计划任务和服务。

**Q：某启动项显示"已禁用"，但任务管理器显示"已启用"？**
可能是两个工具用了不同机制。本工具优先读取 Windows 原生「启动审批」状态，
建议以任务管理器的显示为准做对照，然后用 `--dump` 导出逐项核对。

**Q：点禁用提示权限不足？**
说明该项位于需要管理员的系统位置。按提示确认提权即可，程序会自动以管理员身份完成操作。

**Q：改了之后重启没生效？**
确认该项状态显示为"已禁用"，然后重启电脑。部分服务即使在运行中也需重启才停止。

**Q：程序打不开/闪退？**
① 确认解压时**没有漏掉任何文件**（便携包是多文件目录，不能只拷 exe）；
② 尝试换一个普通目录（如 `D:\Tools\`）再运行；
③ 用 `StartupManager.exe --selftest 结果.txt` 看是否有错误信息。
